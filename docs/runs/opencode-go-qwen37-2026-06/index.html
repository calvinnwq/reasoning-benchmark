Postflight model bench · OpenCode Go · June 2026

OpenCode Go Qwen 3.7 postflight benchmark report

Verdict first: keep opencode-go/glm-5.1 as the postflight incumbent. Qwen 3.7 was mostly clean, but it ran 2.53× to 9.63× slower than GLM on comparable tasks and never produced a quality win big enough to pay for the wait.

Verdict

Keep opencode-go/glm-5.1 as the postflight incumbent. Do not promote Qwen 3.7 into the no-mistakes, GNHF, or postflight gates.

opencode-go/qwen3.7-plus is the better of the two and is fine to keep as an occasional shadow second opinion when latency does not matter. opencode-go/qwen3.7-max is not worth it for this lane.

This was a postflight model bake-off, not a general coding contest. Two Qwen 3.7 challengers ran the same real review tasks GLM already handles. Their reviews were usually clean, but clean was the floor here, and GLM was clean and several times faster. Speed is the whole point of a gate that runs on every branch, so a model that is two to nine times slower for the same outcome does not earn the seat.

Run profile

This benchmark measures real postflight review work, not synthetic reasoning prompts. Each model was handed the same pre-postflight branch and asked to review, autofix clear issues, verify, and clean up history through the gnhf-postflight delegate route on OpenCode Go.

Benchmark type

Live gnhf-postflight runs over real branches. The output is review quality, edits, verification, and wall-clock time.

Tasks

Artshelf NGX-436/437 reconcile core, Momentum NGX-431 built-binary smoke split, Skill Suitcase NGX-386 strict Skillify-10 validation.

Incumbent

opencode-go/glm-5.1 — the current postflight gate model and the bar to beat.

Challengers

opencode-go/qwen3.7-plus and opencode-go/qwen3.7-max, run on the same tasks through the same route.

GLM controls

Existing postflight baselines per task: 527.619s, 398.286s, and 160.367s. They were not rerun in this wave.

What counts as a win

Faster than GLM, or a clear quality edge worth the extra time. Neither challenger cleared that bar.

Every completed Qwen run finished clean, and every completed Qwen run was slower than GLM — from 2.53× on the heaviest task to 9.63× on the lightest. The cheaper the task, the worse the ratio looked, which is the opposite of what you want from a gate that runs constantly on small branches.

Plus vs Max

Between the two challengers, Plus is the only one worth keeping around. It finished every task, verified more thoroughly, and stayed faster than Max. Max was slower on both tasks it completed, lighter on verification, and the one task it could not finish in time was the hardest of the set.

Caveats

  • The GLM numbers are existing postflight baselines, not fresh runs from this wave. The comparison is Qwen-this-wave against GLM-as-it-already-runs.
  • Artshelf with Qwen Max was cut short at about 20m 44s, before verification. It is excluded from the speed range and is not a completed result.
  • This is postflight-review evidence on three tasks, not a universal coding-model ranking. A different lane could rank these models differently.
  • The importer's blocked label on Artshelf Plus is a heuristic mismatch, not a real failure.
On that Artshelf Plus label: the run reported Result: complete with a green build and tests. The importer flagged outcome=blocked only because the report carried a Blockers: section noting a registry-remap product decision. Read it as complete-with-a-note, not blocked.

Recommendation

Keep the gate on GLM

Leave opencode-go/glm-5.1 as the postflight model. Do not promote Qwen 3.7 into the no-mistakes, GNHF, or postflight gates. GLM was clean and several times faster, and these gates run on every branch.

Shadow use only

Keep opencode-go/qwen3.7-plus available as an occasional shadow or second-opinion model when latency is not a concern. Drop opencode-go/qwen3.7-max from this lane.

Next wave, smaller

Run the Wave 2 challengers (kimi-k2.7-code, mimo-v2.5-pro, deepseek-v4-pro) against one Artshelf smoke task first, not all three, before spending a full matrix.
